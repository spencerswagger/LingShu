## 0. 先看三个结论（决定这份草案能落多少）

1. **能直接落 `costRates` 的只有「单一确定价」的渠道**：智谱（API 一手价）、讯飞（1 积分 = ¥0.01，刊例即积分价 × 0.01）、腾讯「分 token 类型计价」的那 10 条。
2. **两类价进不了 `costRates`，必须另想办法**：
   - **阿里**：官方不给「模型 → Credits」系数（只有 qwen3.6-plus 一个算例，`Credits ≈ 刊例价×100` 是我方推算），且套餐是 Credits 制 → **数据集里留空并标「不可用」**。
   - **OpenCode**：官方价是**美元**（Console 按量 USD/百万；Go 是月度美元额度）→ 与「数据集只有人民币」的口径冲突，**不换算、不进表**。
3. **一个格式级缺口，必须 Ark 定**：`costRates` 是「一个模型一个价」，但**火山 Agent Plan 有个人/企业两档价（×0.2 / ×0.3）、腾讯有 4 档价（22.285/19.8/18.687/18.43）**。现有格式没有「档位」维度 → 详见第 6 节，我给了两个候选写法与建议，等 Ark 拍。

## 6. 需 Ark 定的格式问题（本草案不擅自解决）

### 6.1 问题：`costRates` 缺「档位」维度

同一模型在不同套餐档位下单价不同：

| 渠道 | 情况 | 数字 |
|---|---|---|
| 火山 Agent Plan | 个人 vs 企业 | 同一模型 `×0.2` vs `×0.3`（差 50%） |
| 腾讯 Token Plan | Lite / Standard / Pro / Max | `tc-code-latest` 1.1143 / 0.99 / 0.9344 / 0.9215（差 21%） |

### 6.2 两个候选写法（我给建议，不强推）

**方案 A：按「产品线 × 档位」拆 provider（我推荐）**

```
providerId: volcengine-agentplan-personal   / volcengine-agentplan-team
providerId: tencent-tokenplan-lite         / -standard / -pro / -max
```
- 优点：完全符合现有格式（provider = 一个可物化的渠道协议，`costRates` 单值），兰台零改动；`providerId` 规则 `^[a-z0-9][a-z0-9._-]{0,63}$` 也满足。
- 代价：provider 条目变多（火山 2 + 腾讯 4 + 智谱 1 + 讯飞 1 ≈ 8 个），且「同一供应商多条目」要在 UI 里折叠。
- 注意：**模型 key/ID 不许加后缀**（`id` 是上游模型 ID，加 `@team` 会打不中上游）。

**方案 B：数据集只放「API 刊例价」，套餐档位价不进 `costRates`**
- 即：火山/腾讯的套餐价另存一张「套餐倍率表」（0.2.0 展示层用），数据集只承载智谱/讯飞这类「单一价即官方价」的渠道。
- 优点：blast radius 最小，`costRates` 语义保持纯粹（成本倍率 = 对外售价的基准）。
- 代价：套餐对比页拿不到数据集数据，要另开数据源。

**我的建议**：0.2.0 先走 **B**（数据集只收智谱 + 讯飞 + 腾讯分类型 10 条），把「档位价」留给对比页自己的表；等 0.2.0 对比页跑通、确认要用数据集驱动，再按 **A** 拆 provider。理由：档位不是协议维度，塞进 provider 会让「一个 provider = 一套上游接入方式」这个语义变形，且会立刻带来 8 个条目的维护量。

### 6.3 另外两个小问题

1. **分段价（智谱 `glm-5`/`5-turbo`/`5.1`、腾讯 `minimax-m3` 512k 两档）**：`costRates` 无分段维度 → 建议**不填**（宁缺勿错），或正本加 `costRatesTiers`（我不建议 0.2.0 加）。
2. **`CacheRead` 缺失**：火山官方只给输入/输出系数（缓存未单独公布）→ 若强行填 `Input` 同价，会**低估**缓存成本（其他家缓存价通常是输入价的 1/4~1/10）。建议：**火山这批先不填 `CacheRead` 就落不了库（S2 静默 0）**，两条路：① 正本允许「CacheRead 缺省回退 Input」；② 兰台填 `Input` 同价并在备注标「缓存按输入价保守估计」。**这条也请 Ark 定。**

## 7. 兰台落地注意事项（照做即可，无需再问）

1. **数值必须是人民币字面量**：`0.9` 就是 ¥0.90/百万 token；不要写 `9`（角）、不要写 `"0.9元"`、不要乘 100。
2. **三段齐全**：`Input` / `Output` / `CacheRead` 缺一段 → 不报错，但**成本积分静默记 0**（正本 S2）。宁可先不填模型，也别填两段。
3. **`costCurrency: "CNY"` 必须写**（provider 级即可）：代码不读，但 Schema 会卡、人读靠它；缺了会被按 USD 理解（正本 S5）。
4. **别把数据集 URL 挂到 `sync.price_source_url`**：那条路会把人民币当美元 × 6.8，还会污染售价。只挂 `preset.pack_url`。
5. **模型必须内联完整对象**（写字符串整包解析失败、写 `$ref` 被静默丢）；**`externalModelID` 不要填**（灵枢内部 ID，兰台不可知），且它必须是字符串。
6. **带价格的模型必须至少声明一个 `protocols` 键**，否则整条模型（含价格）被静默丢弃（正本 S1）。
7. **上线前跑一次 `POST /api/v1/admin/channel-protocols/sync {"confirm":false}` 干跑**，确认 `Pending` 为空再 `confirm:true`。
