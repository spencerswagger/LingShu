## [P1] 账单详情页请求定位改造（2026-10-26）

- **背景**：账单详情页无法定位「某次请求当初发了什么、为什么失败」。用户要求详情页展示完整增量消息 + 请求参数 + 决策轨迹 + 上游返回 + 用量 + 错误信息；同时一次请求若多候选失败会在账单里刷出多条流水，无法按 request_id 追溯。

  5. 账单列表支持按 `request_id` 搜索；一次请求的多条账单归并为一条主行（`Attempts` 标记，可展开子记录），列表 `Total` 语义为**请求数**；

## [P0] 第一期：订阅池渠道照常开放 + 渠道成本口径 `cost_basis`（2026-11-15）

- **背景**：第一期要定三件事。① **订阅池渠道（Claude / ChatGPT 订阅那类上游）照常对租户开放售卖，不设任何限制**：定价由灵枢自配价目表，上游究竟是订阅还是 API 对租户无感，magpie 那边牌价是 0 还是非 0 都不影响售卖。② 唯一要补的是**成本口径**：价目表新增 `cost_basis` 字段，三选一由运营在配置侧填——订阅摊销（订阅月费 ÷ 该渠道月配额，摊到每 token）、牌价折算（magpie 牌价 × 折算系数）、手工指定（直接填单位成本）。③ **未配置 `cost_basis` 的渠道，毛利报表必须显示「成本未配置」，严禁按 0 计算**（硬约束，不是展示偏好）。此前曾按「按上游类型（订阅/API）限制售卖、牌价为 0 视为不可售、订阅池渠道对租户不可见」设想——**该口径作废，以本条为准**。
- **验收标准**：
  1. **售卖与上游类型无关**：任取一个上游为订阅池的渠道，绑定对外模型后，租户端**能看到、能购买、能正常调用**该模型；链路上不存在按「订阅 / API」拦截、降级、隐藏或加门槛的分支；**不新增任何影响售卖的「渠道类型」开关或字段**（若保留类型标注，只能作运营备注，不得进入定价 / 路由 / 售卖判定）。
  2. **售价由灵枢自配**：magpie 牌价为 0 的渠道与牌价非 0 的渠道，售卖链路行为一致——售价取对外模型售价费率，实际扣费不受上游牌价影响；牌价为 0 不得触发「不可售 / 特殊处理 / 跳过校验」。
  3. **`cost_basis` 三选一可配**：价目表（渠道内部模型的成本侧配置）可配置 `cost_basis`，覆盖三种口径——订阅摊销、牌价折算、手工指定；运营在配置页能选口径、能填对应参数，保存后对**新产生**的账单生效。
  4. **空值语义写死**：`cost_basis` 为空 = **成本未配置 ≠ 0**。空值渠道的账单**不落成本金额（落空值，不落 0）**；真零成本必须显式配「手工指定 + 单位成本 0」，此时正常落 0。判定只认 `cost_basis` 是否为空，**不得**用成本费率是否为空 / 是否为 0 反推，**不得**回落成本费率默认值兜底（现状成本费率有非零默认值，不配也会算出成本，这条必须掐掉）。
  5. **报表可验收**：任取一个未配 `cost_basis` 的渠道，成本页该渠道行成本列显示「成本未配置」，该行**不参与**成本合计、不参与毛利合计；合计行旁必须标注「其中 N 个渠道成本未配置，未计入」，N 与逐行未配置数一致；同一行售价列、请求数、三段 token 照常统计。
  6. **前瞻生效、历史不动**：口径只对新账单生效；已落库账单不回算、不回填；历史成本金额为 0 的行保持原样，**不得**被解释成「未配置」；切换 `cost_basis` 后新旧账单按各自落库快照展示。
  7. **不回归既有口径**：usage 三段 token 计费仍走旁路（日志代理从 magpie 读回 usage 后记账，不进主链路、不阻塞响应；同一 `request_id` 只结算一次，旁路补记不得二次扣费）；上游失败（含 5xx）**整单退预扣**（退还额 = 预扣额，不产生额外扣费）；网关错误响应体顶层带 `request_id`、开发者端不返回成本金额两条不变。
