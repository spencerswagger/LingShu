# V2 第一期「精简表结构与迁移」回滚说明

**回滚点 R0 = 本分支分叉时的 `origin/main`（迁移编号最新为 `0018_call_logs_req_params.sql`）。**

本期只做两件事：① 停掉五类表（`channels` / `channel_keys` / `channel_models` / `channel_events` /
`probe_logs`，含同一套渠道语义的 `channel_protocols` / `protocol_error_stats` / `channel_key_events` /
`channel_model_events` / `channel_tags`）的读写与其上层的自制转发链；② 新增一张**纯新增**迁移。
**没有删除任何表、任何行，也没有做 rename**，因此回滚不需要数据恢复。

---

## 1. 数据库回滚（只需删掉本期新增的对象）

回滚前必须确认：进程已停（避免回滚期间仍有写入），且**先回代码、再删表**（旧二进制只认 0018 的结构，
新表存在不影响它；反过来先删表会让新二进制启动即报错）。

```sql
-- 一次性回滚 0019_v2_facade.sql（可在单事务内执行；不涉及任何旧表数据）
DROP TABLE IF EXISTS reconcile_windows;
DROP TABLE IF EXISTS magpie_keys;

DROP INDEX IF EXISTS uq_external_models_magpie_model;
DROP INDEX IF EXISTS idx_billing_magpie_key_time;

ALTER TABLE external_models   DROP COLUMN IF EXISTS magpie_model;
ALTER TABLE billing_records   DROP COLUMN IF EXISTS magpie_key_name;
ALTER TABLE billing_records   DROP COLUMN IF EXISTS estimated;
ALTER TABLE billing_records   DROP COLUMN IF EXISTS upstream_usage;

-- 让迁移框架在下次启动时重新应用 0019（若将来又想上这一期）
DELETE FROM applied_migrations WHERE name = '0019_v2_facade.sql';
```

说明：
- 两个新表在本期**没有任何写入方**（对账任务与 key 同步都属于第二期），删表零风险。
- 四个新列的 `estimated` 有 `NOT NULL DEFAULT false`，若本期已有账单写入，删除该列会一并丢“估算标记”，
  但金额、三段 token、费率等计费口径列一律不动，**历史账单金额不受影响**。
