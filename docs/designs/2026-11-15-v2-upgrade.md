# 老版本（V1）升级到 V2 迁移链 · 评估与执行手册

日期：2026-11-16　适用分支：`feat/lingshu-v2-sync-config`（V2 唯一迁移链）
状态：**评估稿**。其中「0024 与现有代码冲突」是**阻塞项**，未摘代码前不许在生产跑 0024（见 §4）。

## 1 适用范围与目标态

| 项 | 旧（`origin/main`，迁移到 0018） | 新（V2 链，0019–0024） |
| --- | --- | --- |
| 路由主体 | `channels` / `channel_keys` / `channel_models` / 标签族 | `internal_models`（网关镜像）+ `external_models.bound_internal_ref` |
| 计费口径 | 账单带 `channel_key_id`，成本无真源 | `billing_records` 七列归因（`upstream_provider/account/model/protocol/ledger_entry_id/cost_source/request_id`） |
| 上游用量 | 无 | `ledger_entries`（最小九字段）+ 同步轮次（60s 窗口、offset 续拉、幂等） |
| 对账 | 无 | `reconcile_windows`（60s 窗，四计数列 + alarm_streak + scroll_offset） |
| 预扣 | 直接扣 + 失败退回（无登记） | V2 曾用 `credit_holds`（已随 V3 代理链下线，表结构保留、历史行不清理） |
| 订阅成本 | 无 | `subscriptions`（月费/年费，按用量分摊进 `cost_credits`，`cost_source='amortized'`） |

迁移集合（唯一链，字典序执行，`0024` 最后）：

```
0019_v2_topology.sql  0020_v2_billing_attribution.sql  0022_v2_ledger.sql
0023_v2_reconcile.sql  0023b_v2_reconcile_repair.sql  0023c_v2_reconcile_counts_backfill.sql
0024_v2_drop_legacy.sql
```

`0021` 是**空号，不复用**（原 `0021_v2_drop_legacy` 已改名 0024 排到末尾）。

## 2 升级前必做（缺一条就别开始）

1. **备份**：`pg_dump -Fc -Z6` 全库，记录文件字节数与 sha256。
   参考实测规模：1,625,951 行 / 32 表 → 4.83s / 37,152,782 B（见 `backend/docs/plans/2026-11-15-v2-0024-preflight-evidence.md`）。
2. **行数快照**：15 张保留表逐表 `count(*)` 存文件（0024 前后必须一致，允许因新写入而增加，不允许减少）。
3. **迁移记账探测**：

   ```sql
   SELECT name FROM applied_migrations ORDER BY name DESC LIMIT 5;
   ```

   - 期望最后一条是 `0018_call_logs_req_params.sql`；
   - 若出现 `0019_v2_facade.sql` / `0020_reconcile_blocked_status.sql` → **该库跑过旧线**，见 §3；
   - 若出现任何 `0021_v2_*` → 停手，先弄清是哪条分支写的。
4. **停进程再迁移**（`0024` 会删列）：迁移期间不允许有写业务表的进程在跑，否则会出现「列刚删、进程还在写」的 42703 风暴。

## 3 旧线库（跑过 `0019_v2_facade`）的处置

三条分支（slim-migrate / usage-billing / magpie-passthrough）里的 `0019_v2_facade.sql` 是**同一个 blob**（sha256 相同，4930 B）。
机制先说清（两种故障别混）：迁移器的幂等键是 `applied_migrations.name`，即**完整文件名**，不是版本号。

- 两个**不同文件名**的 `0019`（`0019_v2_facade` 与 `0019_v2_topology`）**都会执行** —— `facade` 字典序在前，先把错形窗口表建出来；
- **同名文件不同内容**才会被静默跳过（后合并的那份零报错、库不动）。

在一个跑过 `0019_v2_facade` 的库上再跑本链，现象是「文件逐个 exit 0、`applied_migrations` 记到 0023、零报错，但库是坏的」：
`reconcile_windows` 被 `CREATE TABLE IF NOT EXISTS` 整段跳过，与干净基线差 96 行。

判定（三条都要查，不能只信 `applied_migrations`）：

```sql
-- a) 表在不在
SELECT to_regclass('public.magpie_keys'), to_regclass('public.reconcile_windows');
-- b) 关键列在不在
SELECT column_name FROM information_schema.columns
 WHERE table_name='reconcile_windows' ORDER BY ordinal_position;
-- c) 约束形状
SELECT conname FROM pg_constraint WHERE conrelid='reconcile_windows'::regclass;
```

处置：**旧线库只可能是 dev/test**（生产未跑过旧线）。不要试图用一条修形迁移自愈——
`0023` 自己就会在旧形状的 `ALTER COLUMN local_count DROP NOT NULL` 处 42703 硬失败，
后续文件排不上。正确做法是重建（`createdb` + 本链 + 数据按需导入）或用备份还原后重跑。

## 4 阻塞项：`0024` 与现有代码冲突（P0，必须先摘代码）

`0024` 删 10 张渠道族表 + `billing_records.channel_key_id` / `sessions.channel_key_id` / `tokens.tag_id`，
而当前代码仍在使用它们。实测后果不是「部分接口报错」，而是**进程启动即 `exit=1`**：
`main.go` 迁移阶段之后 `SyncFromDB` 查 `channels` → 42P01，发生在首请求之前。

因此升级顺序只有两条合法路径：

- **A（推荐）**：先发「摘代码」版本（auth / billing 读写 / session / console / tag 五处），确认进程能起、门禁绿，再跑 `0024`；
- **B**：同一个发布窗口内一起上（代码与迁移同批），中间不留「只合一半」的窗口。

不许的做法：先跑 `0024` 再等代码 —— 那段窗口里服务起不来，且 `billing` 写路径会持续 42703。

## 5 运行参数与环境变量

| 键/变量 | 作用 | 缺省行为 |
| --- | --- | --- |
| `UPSTREAM_AUTH_HEADER` / `UPSTREAM_AUTH_VALUE` | 上游凭据（只在环境变量里，配置表与代码都不存） | 不注入 |
| `UPSTREAM_LEDGER_URL` / `UPSTREAM_ADMIN_KEY` / `UPSTREAM_ADMIN_AUTH_HEADER` | 账本拉取端点与凭据 | 未配 → 同步只记 blocked，日志告警 |

注意：`/v1` 由 nginx 直连代理侧网关端口（不经过灵枢后端）；账本链路可用性只看 `UPSTREAM_LEDGER_URL`（env，未配 = 同步轮跳过并告警）。

## 6 数据与报表影响

- 历史账单的 `upstream_*` 归因为 NULL（升级前的行不会凭空有值）→ 盈亏页按 `(unknown)` 单独成组；
- 历史账单 `cost_credits` 为 NULL → `cost_source` 必须是 `'none'`（F10 跨列 CHECK），毛利率在无收入时为 `null`；
- 渠道名/密钥名维度**永久消失**（0024 删表）；历史一次性回溯只能读 `call_logs` 的同名列快照；
- 统计主维度从「渠道」切到 `internal_model_id`：同一内部模型下多个渠道密钥的行会合并（总额不变、行数变少且可解释）。

## 7 回滚

| 对象 | 可逆性 | 做法 |
| --- | --- | --- |
| 0019 / 0020 / 0022 / 0023 / 0023b / 0023c | 可逆 | 删表/删列/删约束（数据是派生或新增，无历史数据损失） |
| **0024** | **不可逆** | 只能从 `pg_dump` 还原；或 `ALTER TABLE ... RENAME` 保底后人工补 |
| 代码 | 可逆 | revert 提交；注意 revert 代码而不还原库会立刻 42703 |

## 8 验收清单（跑完逐条勾）

- [ ] 15 张保留表全在、10 张退役表全不在（`db.RetainedTables()` / `RetiredTables()` 对照）；

- [ ] 一次真实转发请求走完：代理侧网关 200 → 账本轮询拉到用量 → 账单落库；
- [ ] 60s 后 `reconcile_windows` 出现计数列非 NULL 的行；
- [ ] 配了账本端点时：同步轮次 `page/offset` 有日志、`ledger_entries` 有行；
- [ ] `/api/v1/admin/ops/pnl` 与 `/api/v1/admin/ops/reconcile-windows` 能返回（未配数据时返回空数组而非报错）。
