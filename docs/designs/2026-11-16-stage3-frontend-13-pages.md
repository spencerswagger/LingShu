## 1 计数规则与范围

### 1.1 计数规则

- 按**业务页面**计：一个路由页面算 1 页；管理端/开发端同业务的两种视图（同组件、不同 scope）算**同一页**，不重复计。
- 登录 / 注册 / 改密 / 403 / 布局壳**不计入**。
- 弹窗、抽屉（如「新建订阅」「账单详情块」）不单独计页，算所属页面的交互。

### 1.2 明确不在 13 页内的旧页面（不许照搬）

| 旧页面 | 处置 | 理由 |
|---|---|---|
| 渠道 / 渠道协议 / 渠道密钥 / 渠道模型 | **下线** | 0024 删 10 张渠道族表；能力归网关侧；接口 410 |
| 语义标签 | **下线** | `semantic_tags`/`channel_tags` 删除；`tokens.tag_id` 删除，标签不再影响路由 |
| Auto 模型 | **下线** | `auto_models`/`auto_model_members` 删除；auto 名需逐条转为对外模型（数据迁移动作，不是页面） |
| 会话列表 / 会话详情 | **下线** | V2 前端 13 页无会话页（裁定原文）；新链路不写 `sessions` |
| 成本页（V1） | **由盈亏页取代** | V1 成本页 JOIN `channel_keys`/`channels`，0024 后必 500；V2 成本只有 `ledger`/`amortized`/`none` |
| 服务状态页 | **并入拓扑页** | V2 无探活/渠道健康表；可展示的只有同步新鲜度与供应商覆盖，属拓扑页内容 |

> 「预扣 / 差额结算」不单开页面：它是单笔请求的资金轨迹，落在账单详情（§3-P09）的「资金轨迹」块；全局视图在盈亏页。

## 3 逐页规格

> 每页固定五段：用途 / 关键交互 / 依赖接口 / 空态与异常 / 可验收判断条件。接口编号见 §4。

### P01 统计概览

**用途**：一屏回答「用了多少、收了多少、成本从哪来、现在多快」。

**关键交互**
- 时间范围（近 24h / 7d / 自定义，读 `KPI.WindowFrom/WindowTo/WindowMode`，前端不自拼）。
- KPI 卡：请求数、成功率、Token 合计、收入积分、成本积分、毛利率。
- 成本来源条：`ledger` / `amortized` / `none` / 未配置（`cost_source IS NULL`）四段，点击跳到账单查询（带筛选）。
- 模型广场：对外模型 TOP N（按积分、请求数切换）。
- 实时区：近 60 分钟 RPM / TPM / 活跃令牌数 / 在飞请求数；30s 自动刷新。

**依赖接口**：M1（dashboard，去渠道/密钥/会话计数，加成本来源与拓扑覆盖）、M2（live，去会话准入语义）。

**空态与异常**：无数据时四段成本条显示「暂无账单」而不是全 0 饼图；接口失败展示 `request_id` 与重试。

**可验收判断条件**
1. 页面不出现「会话」「渠道」「密钥」「Auto」字样与入口；`Sessions`/`Channels`/`Keys` 字段即使接口返回也不渲染。
2. `cost_source IS NULL` 的金额显示「成本未配置」，**不显示 0.00**；`none` 显示「无成本口径」，两者文案不同。
3. 收入为 0 时毛利率显示「—」，不显示 0% 或 100%。
4. 实时区只显示速率类指标，不出现会话列表/在线用户列表。
5. 时间范围切换后所有卡片同步刷新，无「部分卡片停留在旧窗口」。

**Mock**：M1/M2 未就绪时按契约字段造 2 个时间窗数据；实时区 mock 只造速率数字，不造会话数组。

### P02 上游拓扑

**用途**：让运营看清网关侧「供应商 → 账号 → 内部模型 → 对外模型」四层关系，以及同步是否新鲜。

**关键交互**
- 四列/画布视图切换；节点显示 `provider_ref`、`kind`（direct/group）、`stale` 灰化、`context_len`。
- 顶部状态条：最后同步时间、同步结果（成功/失败原因）、内部模型数、未绑定对外模型数、`stale` 数。
- 「立即同步」按钮（T3），执行中禁用并轮询/回填结果。
- 点对外模型节点 → 打开 P03 编辑；点未绑定内部模型 → 提示「无对外模型，不售卖」。
- 画布拖拽后保存坐标（T2，可延后；未就绪时自动布局，刷新按自动布局）。

**依赖接口**：T1（拓扑聚合）、T3（手动同步）、T2（坐标保存，可延后）。

**空态与异常**：从未同步 → 空态「尚未同步网关拓扑。同步前录入订阅/绑定模型都会被拒绝」+ 主按钮；同步失败 → 红色条显示原因与上次成功时间，**不清空**已有快照。

**可验收判断条件**
1. 四层关系与 `internal_models`/`external_models.bound_internal_ref` 数据一致：未绑定内部模型计入「未绑定」计数，且计数与列表条数相等。
2. `stale=true` 节点灰化并有「上期快照」标识；同步成功后灰化消失。
3. 同步失败时页面保留旧数据 + 展示失败原因 + 上次成功时间；不出现空白页。
4. 拓扑为空时，从 P04 录入订阅返回 `topology_not_synced`，页面能跳回本页同步。
5. 本页不展示任何凭据/密钥/上游 URL（`sys_configs` 的 `base_url` 仅系统页可见）。

### P03 对外模型与绑定

**用途**：维护售卖面：对外模型名、绑定哪个内部模型、三段售价、启停。

**关键交互**
- 列表：对外名、绑定状态（已绑定 `provider/model` / 未绑定）、售价三段、启用、更新时间。
- 新建/编辑：绑定下拉（T4，按 provider/kind 分组、`stale` 候选禁用并标注）、三段售价、上下文分档、时段系数、启用开关。
- 保存绑定走 T5（唯一真源 `external_models.bound_internal_ref`），不走通用 PUT 的隐式字段。
- 「未绑定 = 不售卖」提示必须在保存前出现；`/v1/models` 预览（可选）显示该模型是否会出现。
- 价格参考/应用售价沿用既有能力（`price-reference`、`apply-price`、`sync-prices`）。

**依赖接口**：T4（内部模型候选）、T5（绑定）、M3（模型 CRUD 去掉 `magpie_model`/渠道/限流字段；dev 列表按 `bound_internal_ref IS NOT NULL` 过滤）。

**空态与异常**：候选为空 → 「先同步拓扑」；绑定了一个已 `stale` 的 ref → 保存时 400，文案「该内部模型本轮未在网关出现，请重新选择」。

**可验收判断条件**
1. 绑定保存后，`GET /v1/models` 出现该对外名；解绑后消失。
2. 未绑定模型在列表显示「不售卖」标签，且不能被开发者端看到。
3. 开发者端模型页不返回 `bound_internal_ref`、内部模型名、成本/渠道字段（负向断言）。
4. 绑定候选只来自 T4，输入不存在的 ref 必 400，不允许自由文本落库。
5. 页面不出现 `magpie_model`、`rate_limit`、`health_probe`、`reliability` 等已下线字段。

### P04 订阅账本

**用途**：录入上游账号的固定订阅费，让 A5 月费分摊真正有数据；并让「摊不出去」可见。

**关键交互**
- 列表：订阅方/账号/整期费用（原币+积分）/周期/账期/状态/本期已摊/未摊出/操作。
- 新建/编辑表单：字段与校验完全按 `2026-11-16-subscription-entry-standard.md` §8。
- 提交后必须展示 `WillAmortize` 与 `BlockReasons`；`false` 时展开原因码与处置按钮。
- 「本期分摊明细」抽屉（S4）：可摊账单列表、摊得金额、`Unallocated`、原因码。
- 「结转到本期」（S5）、「立即重算」（S6）。
- 顶部固定条：本月 N 条未摊出、合计 M 积分；为 0 时隐藏。

**依赖接口**：S1–S7、T1（provider 候选）。

**空态与异常**：无订阅 → 文案「不录订阅 = 盈亏页成本永远少一笔固定支出」+ 新建按钮；`topology_not_synced` → 阻断并跳 P02。

**可验收判断条件**
1. 录入一条满足 C1–C4 的订阅后，响应 `WillAmortize=true`、`BlockReasons=[]`。
2. ≤5 分钟（或点 S6）后，该账号当期账单出现 `cost_source='amortized'`，`Σ cost_credits = PriceCredits`（±0.00001）。
3. 重复录入同 `(Provider, Account)` 返回 409 并引导编辑，列表仍 1 行。
4. `cycle_start` 为空/过期时，列表状态分别为「缺账期」「已结束需结转」，且不能显示为「分摊中」。
5. 「本期已摊 + 未摊出 = 整期费用」在页面上可核对（误差只允许分币级）。
6. 移动端 375px 单列表单可用，无横向滚动。

### P05 账本流水

**用途**：看上游账本条目（变动成本真源）与拉取新鲜度，回答「成本数据是不是最新的」。

**关键交互**
- 筛选：时间范围、`provider`、`provider_account`、`model`、`ledger_id` 精确查。
- 列表：`occurred_at`、provider、账号、model、tokens_in、tokens_out、`cost_credits`、`ledger_id`（可复制）。
- 新鲜度卡：`max(occurred_at)` 滞后秒数、最近成功拉取时间、`blocked`/`error` 窗口数、待补拉 offset 合计、本轮预算是否耗尽。
- 点击行 → 关联账单（按 `billing_records.ledger_entry_id` 反查，跳 P09）。

**依赖接口**：L1（entries 分页，`occurred_at ASC` 作为拉取序、展示可倒序）、L2（status 聚合）。

**空态与异常**：`ledger_enabled=false` → 「账本拉取已关闭」空态 + 去系统页；从未拉到 → 「账本为空，成本只剩订阅摊销」。

**可验收判断条件**
1. 滞后 >180s 显示橙色「账本不新鲜」，>15 分钟显示红色「对账不可用」。
2. `blocked`/`error` 窗口数 >0 时给出跳转 P06 的链接。
3. 列表总数与筛选条件一致（服务端 count，不用当前页长度冒充）。
4. `ledger_id` 可一键复制，重复条目只出现一次（唯一键保证）。
5. 页面不展示金额币种换算（账本 `cost_credits` 已是积分）。

### P06 对账窗口

**用途**：逐 60s 窗口比对灵枢账单与上游账本，让漏账「看得见」。

**关键交互**
- 顶部汇总：各状态窗口数、最长 `alarm_streak`、偏差 >2% 窗口数、待补拉窗口数（O1；未就绪时前端按当前页聚合，标注「按当前页统计」）。
- 列表：窗口起止、状态（五值）、本地/上游笔数、本地/上游 token、偏差率、`alarm_streak`、`scroll_offset`、`checked_at`。
- 状态筛选 + 时间范围（默认近 60 分钟，最长 24h）。
- 行展开：`detail` 中的 `sync.*`、`reconcile.*`、`skip_reason`；只作排障，不参与判定。

**依赖接口**：M4（补 `skip_reason`、五值状态、计数 null 语义、`scroll_offset`）、O1（汇总，可延后）。

**空态与异常**：无窗口 → 「同步未运行或账本关闭」并给出原因；`skipped` 必须显示 `skip_reason` 文案，不许只显示状态词。

**可验收判断条件**
1. 计数列为 null 显示「—」并标注「未计算」，**不显示 0**。
2. `blocked` 行显示待补拉进度（`scroll_offset`），`error` 行显示错误原因。
3. `skipped` 行显示四种原因之一（`ledger_disabled`/`ledger_unavailable`/`fetch_blocked`/`service_down`）的中文文案。
4. 连续 `alarm_streak ≥ 3` 的行高亮并排在前面（或可一键筛出）。
5. 页面不出现金额对比（只比笔数与 token）。
6. 四计数尚未写入的窗口，页面不得显示「已对账」。

### P07 盈亏

**用途**：收入（售价积分）− 成本（账本 + 摊销）＝ 毛利，按供应商/账号/模型拆。

**关键交互**
- 时间范围 + 分组维度（`provider` / `account` / `model`）。
- 汇总卡：请求数、Token、收入、成本、变动成本（`LedgerCost`）、固定成本（`AmortizedCost`）、毛利、毛利率、`Uncosted`。
- 趋势图（O2）：按小时/天，收入/成本/毛利三条线；切换时间粒度。
- 分组表：每组一行，列同上；支持排序（按毛利/收入）。
- `Uncosted>0` → 顶部黄条「N 笔账单无成本口径，当前毛利偏高」，点击跳账单查询（筛成本来源=未配置）。
- `Truncated=true` → 提示「分组超过 200，只显示前 200」。

**依赖接口**：M5（`Uncosted` 拆成「未配置」与 `none` 两个计数）、O2（趋势）。

**空态与异常**：无收入 → 毛利率「—」；无成本但收入 >0 → 黄条 + 成本列「0（无成本数据）」需与真实 0 区分。

**可验收判断条件**
1. 汇总行 `收入 − 成本 = 毛利`，`毛利 ÷ 收入 = 毛利率`，数值到 5 位小数后仍成立。
2. 收入 ≤0 时毛利率为「—」（接口 `MarginPct=null`）。
3. 变动成本 + 固定成本 = 成本合计（分币级）。
4. `Uncosted` 与成本来源四段（ledger/amortized/none/未配置）在页面上可互相核对。
5. 切换分组维度后，各维度合计相等（同一时间窗）。
6. 不显示渠道/密钥维度。

### P08 账单查询

**用途**：按人、模型、归因、成本来源筛单笔账单，支撑排障与对账。

**关键交互**
- 筛选：时间、用户、令牌、对外模型、状态、计费模式、`upstream_provider`、`upstream_account`、`upstream_protocol`、`cost_source`、`HasLedger`。
- 列表：时间、用户、对外模型、上游模型、协议、供应商/账号、三段 token、收入积分、成本积分 + 来源、状态、耗时、`request_id`。
- 汇总栏：请求数、积分合计、Token 合计、失败数（`Total` = 请求数，文案同步）。
- 行点击进 P09；筛选条件写入 URL，可分享/回退。
- 空值展示：成本 `NULL` → 「成本未配置」；历史行（`cost_source IS NULL` 且金额非空）→ 「历史（口径未知）」。

**依赖接口**：M6（加归因/成本来源筛选，去 `ChannelKeyID`）、M7（stats 去渠道分组、加成本来源）。

**空态与异常**：筛选无结果 → 保留筛选条件 + 「清除筛选」；接口 400 时定位到具体参数。

**可验收判断条件**
1. 筛选组合在 URL 中可还原，刷新后结果一致。
2. 历史数据（`cost_source IS NULL`）与 `cost_source='none'` 文案不同、颜色不同。
3. 开发者端不出现成本列、他人用户/令牌列、`internal_model_id`、`upstream_account`。
4. 列表 `Total` 等于去重后的请求数（`Group=0` 时），与分页总页数一致。
5. 不再出现「渠道密钥」筛选项；带 `ChannelKeyID` 的旧链接不报 500（忽略该参数）。

### P09 账单详情

**用途**：单笔请求的完整解释：用量怎么算、成本从哪来、预扣怎么结算、失败为什么。

**关键交互**
- 头部：`billing_id`、`request_id`、时间、状态、用户、令牌、对外模型/上游模型、协议、耗时/首包。
- 用量与计费：三段 token、`R`、时段系数、上下文系数、售价费率、实扣积分。
- 归因：`upstream_provider` / `upstream_account` / `upstream_protocol` / `upstream_model`，缺失显示「无归因」。
- 成本：`cost_source`（ledger/amortized/none/未配置）、`cost_credits`、关联账本条目（`ledger_id`/`occurred_at`，可跳 P05）。
- 资金轨迹：预扣金额/状态/`expires_at`、结算差额、退款、钱包流水（`credit_holds` + `credit_flows`）。
- 错误：`error_message`、上游错误体（脱敏）、`request_id` 可复制。
- 开发者端：只保留请求侧（用量、状态、错误、耗时），无成本/上游账号/内部模型。

**依赖接口**：M8（管理端补归因七列、成本、预扣/结算、账本条目；dev 白名单重做）。

**空态与异常**：账本条目未匹配 → 「成本待结算」而不是 0；预扣不存在（失败请求）→ 「未预扣/已退款」。

**可验收判断条件**
1. 金额恒等式：`预扣 − 退款 + 差额结算 = 实扣积分`（或「预扣 − 实扣 = 退回」），页面显示等式结果。
2. `cost_source='none'` 与 `cost_source IS NULL` 文案不同（「无成本口径」vs「历史未知」）。
3. 账本条目已匹配时展示 `ledger_id`，未匹配时显示「待结算」，不显示 0。
4. 开发者端页面**负向**断言：无 `cost`/`cost_source`/`upstream_account`/`internal_model_id`/`Rates` 键。
5. 复制 `request_id` 可在 P08 精确查回该单。

### P10 用户与钱包

**用途**：用户 CRUD、余额与流水、充值/调整。

**关键交互**
- 列表/搜索/新建/编辑/批量删除/重置密码/重置 TOTP。
- 详情：基本信息、余额、计费模式、钱包流水（时间/类型/金额/余额后/备注）。
- 充值、设为、调整（带二次确认与必填备注）。
- 计费模式：本期只允许 `sale`；`cost` 选项禁用并说明「V2 无成本单价来源，成本模式停用（口径 D-1）」。

**依赖接口**：既有 `/admin/users*`、`/wallet*`，无改造。

**空态与异常**：余额为 0 显示 `0.00000`（真实 0），不是「—」；调整导致负余额 → 400 并保留输入。

**可验收判断条件**
1. 钱包操作后余额与流水末行「余额后」一致（分币级）。
2. 不允许负余额；错误文案点名字段。
3. `cost` 模式不可选，已有 `cost` 用户有明确标注（不影响历史账单展示）。
4. 列表与详情对同一用户余额展示一致。
5. 非 ADMIN 访问返回 403 页面。

### P11 令牌

**依赖接口**：M9（去 `tag_id` 读写与 DTO 字段）。

**空态与异常**：无令牌 → 引导新建；密钥查看失败 → 显示 `request_id`。

**可验收判断条件**
1. 页面与接口均无「标签」概念；0024 后列表/创建/轮换不报 42703。
2. 查看密钥需二次确认，操作后有审计记录。

### P12 系统设置

**用途**：上游接入三键、计费参数、价格同步与告警的统一配置页。

**关键交互**
- 上游接入：`upstream.base_url`（仅 http/https、拒绝 `user:pass@`、去尾斜杠）、`upstream.timeouts`（两字段 1000–600000ms）、`upstream.degrade`（三开关）。
- 计费参数：`billing.r`、`billing.cny_rate`、上下文分档、时段系数（沿用既有块）。
- 价格同步：watchlist、立即同步、告警列表与「已处理」。
- 保存后回读校验；对非法值给字段级错误，不整块丢弃。
- 页面**不出现**任何凭据/密钥；`base_url` 也只在管理员可见。

**依赖接口**：M10（三键 schema、旧键下线、掩码、非法值 400）。

**空态与异常**：`base_url` 为空 → 「未接入：/v1 返回 410/503」提示；保存失败 → 保留编辑内容。

**可验收判断条件**
1. 三键保存后读回一致；`base_url` 带凭据或非 http(s) 返回 400。
2. `timeouts` 越界返回 400；`degrade` 非布尔返回 400。
3. 旧键（`upstream.timeout_ms`、布尔 `upstream.degrade`）不再出现在页面；提交旧键返回 400。
4. 修改 `degrade.passthrough_enabled=false` 后，`/v1/*` 返回 503（可实测）。
5. 页面无任何 secret/key 字段。

## 7 全局验收口径（每页都适用，Gate 逐条过）

| # | 项 | 口径 |
|---|---|---|
| 1 | 权限 | 开发者端不得出现成本、上游账号/供应商、内部模型、他人用户/令牌；负向断言必须有用例（参照 `dev_redact_test.go`） |
| 2 | 空值与 0 | 「未计算/未配置/历史未知」一律显示「—」或专属文案，**不许显示 0**；真实 0 正常显示 `0.00000` |
| 3 | 金额单位 | 页面金额一律标「积分」；元只出现在订阅录入（并实时显示折算积分） |
| 4 | 时间 | 接口传 RFC3339，页面按本地时区展示；跨时区不改变排序 |
| 5 | 分页 | 默认 20，最大 200；筛选条件写 URL，可分享/后退 |
| 6 | 三态 | 每个列表/卡片必须有加载、空、错误三态；错误态展示 `request_id` 与重试 |
| 7 | 移动端 | 375px 单列、无横向滚动、正文 ≥14px、操作按钮不重叠 |
| 8 | 禁用词 | 13 页不得出现「渠道」「渠道协议」「渠道密钥」「标签」「Auto 模型」「会话列表」入口（历史数据说明除外） |
| 9 | 不 500 | 任何页面不得引用 0024 已删表/列；发现 500 即阻塞合入 |
| 10 | 性能 | 本地百万行库量级下首屏 P95 < 2s；盈亏/账单必须服务端分页与聚合，不许拉全量到前端算 |
| 11 | 可解释 | 任何「成本为 0/空」「无归因」「未摊出」都必须能点开看到原因，不许只有一个数字 |

## 8 给三方的落地提示

- **View**：先按 §2 建 13 个路由与菜单（12 菜单 + 详情子页），再按 §6 批次填内容；每页开工前先确认 §4 对应接口编号，接口未就绪就按 §5 做壳。
- **Core**：按 §4 顺序出接口；P0 的 24 条里，M9（token tag）、M3（model 字段）、M8（billing 列）是 0024 的**运行时 500 闸门**，优先于新功能。
- **Gate**：按 §3 每页的「可验收判断条件」+ §7 全局 11 条出验收单；缺 mock 标识、缺空值语义、缺 dev 负向断言，直接判不可合入。
