# 渠道成本口径 `cost_basis`（第一期口径正本）

- 日期：2026-11-15
- 状态：**生效**。取代 2026-11-15 之前所有「按上游类型（订阅 / API）限制售卖」「牌价为 0 视为不可售 / 特殊处理」「订阅池渠道对租户不可见 / 加门槛」的口径。
- 范围：产品口径与验收标准。字段落库形态、SQL、接口字段名属技术方案，由架构定；本文只规定「运营能配、报表能读、空值语义不变」。

---

## 1. 定稿口径（唯一有效版本）

1. **订阅池渠道照常对租户开放，不设任何限制。** Claude / ChatGPT 订阅那类上游，与 API 上游在售卖链路上**完全等价**：模型照样上架、租户照样能看见、能购买、能调用。
2. **定价由灵枢自配价目表。** 上游是订阅还是 API，对租户无感；**magpie 牌价是 0 还是非 0，都不影响售卖**（售价取灵枢对外模型售价费率，与上游牌价无关）。
3. **成本口径由 `cost_basis` 表达**，价目表新增该字段，三选一由运营在配置侧填：订阅摊销 / 牌价折算 / 手工指定（细则见 §2）。
4. **未配置 `cost_basis` = 成本未配置 ≠ 0。** 毛利报表该渠道成本列显示「成本未配置」，**严禁按 0 计算**，且不参与成本合计与毛利合计（见 §2.4）。
5. **其余不变**：usage 三段 token 计费仍走旁路（日志代理从 magpie 读回 usage 后记账）、网关错误体顶层带 `request_id`、上游失败（含 5xx）整单退预扣。

> 为什么单独立这个字段：现状「成本费率」有非零数据库默认值，**不配也会算出成本**。所以「成本有没有配」必须有一个显式的、独立的判定入口，不能靠费率是否为空 / 是否为 0 反推——否则「成本未配置」永远显示不出来，报表会拿默认费率当成真成本。

---

## 2. `cost_basis` 细则

### 2.1 三个口径的语义与取数

| 口径 | 语义 | 需要运营填的参数 | 取数来源 | 参数 / 数据缺失时 |
|---|---|---|---|---|
| 订阅摊销 | 订阅月费 ÷ 该渠道月配额，摊到每 token | 订阅月费（元 / 月）、该渠道月配额（token / 月） | 运营填写（月费按订阅实际支出，月配额按该渠道当月可用额度） | 任一缺失 → **成本未配置**（空值，不落 0） |
| 牌价折算 | magpie 牌价 × 折算系数 | 折算系数（默认 1.0） | magpie 牌价由日志代理回传；系数由运营填 | **牌价数据缺失 → 成本未配置**；系数未填按 1.0；**牌价明确为 0 → 成本 0（真实 0，落 0）** |
| 手工指定 | 直接填单位成本 | 单位成本（元 / token），可沿用现有三段成本费率 | 运营填写 | 未填 → **成本未配置**（空白 ≠ 0） |

**「数据缺失」与「数据为 0」必须分开**：牌价缺失 = 不知道成本 → 未配置；牌价 = 0 = 已知零成本 → 真实 0。手工指定填 0 同理是真实 0。这一条决定报表上是「成本未配置」还是「0.00」。

### 2.2 三段 token 如何映射到单价

计费是三段（纯输入 / 缓存读 / 输出），成本口径必须能落成三段单价：

- **牌价折算**：magpie 牌价本身分段（输入 / 输出 / 缓存读），逐段乘折算系数 → 三段单价。
- **手工指定**：直接填三段成本费率（现有成本费率即载体）。
- **订阅摊销**：月费 ÷ 月配额只能得到**一个**每-token 单价，而订阅配额本身不区分段 → 默认**三段同价**（同一单价乘三段 token 数）。
  - ⚠️ 待 spencer 确认：若要求三段差异化，则运营需另填「段比例」（如输出 = 输入 × k），届时按比例分摊。**未确认前按三段同价实现**，不留空档。

### 2.3 生效范围

- **前瞻生效**：口径只对新产生的账单生效；已落库账单不回算、不回填。
- 切换 `cost_basis` 后，新旧账单在报表上按各自落库快照展示，同一行可能出现「部分区间已配置、部分未配置」——报表按行聚合时以「该行是否存在未配置账单」为准标注（见 §2.4）。
- 历史成本金额为 0 的行保持 0，**不得**被解释成「未配置」。

### 2.4 空值语义（硬约束，写死）

1. **唯一判定入口** = `cost_basis` 是否为空（未配置）。**禁止**用「成本费率是否为空 / 是否为 0」反推；**禁止**回落默认成本费率兜底。
2. 未配置渠道的账单**成本金额落空值（NULL），不落 0**；真零成本必须显式配「手工指定 + 单位成本 0」，此时落 0。
3. 报表判定只认「成本金额为空 = 未配置」：成本列显示「成本未配置」，该行不参与成本合计、不参与毛利合计；合计行旁标注「其中 N 个渠道成本未配置，未计入」，N 与逐行未配置数一致。
4. `cost` 计费模式的用户**不得路由到未配置 `cost_basis` 的渠道**（没有单价无法扣费）：命中按可读错误拒绝，**不得**按 0 成本扣费，**不得**静默回落售价扣费。

## 3. 枚举 key 命名候选（**待 spencer 确认，未定死**）

spencer 只给了语义、没给 key 名称。按项目现有命名习惯（配置 JSON 走 snake_case，枚举值小写，与 `pricing_mode` 的 `sale` / `cost` 同风格）拟三组候选：

### 候选 A（推荐：短、与现有风格一致）

| key | 语义 | 取数来源 |
|---|---|---|
| `subscription` | 订阅摊销 | 运营填的订阅月费 ÷ 该渠道月配额，摊到每 token |
| `list_price` | 牌价折算 | magpie 牌价（日志代理回传）× 运营填的折算系数 |
| `manual` | 手工指定 | 运营直接填的单位成本（三段成本费率即载体） |

### 候选 B（更自解释，略长）

| key | 语义 | 取数来源 |
|---|---|---|
| `subscription_amortized` | 订阅摊销 | 同上 |
| `list_price_scaled` | 牌价折算 | 同上 |
| `manual_fixed` | 手工指定 | 同上 |

### 候选 C（动词化，最短）

| key | 语义 | 取数来源 |
|---|---|---|
| `amortize` | 订阅摊销 | 同上 |
| `scale` | 牌价折算 | 同上 |
| `fixed` | 手工指定 | 同上 |

配套参数名候选（同组）：`monthly_fee` / `monthly_quota` / `scale`（折算系数）/ `unit_cost`。
若 `cost_basis` 只存字符串枚举，参数建议收在 `cost_basis_params` 里（**待架构确认落库形态，不影响口径**）。

> 命名风险提示：候选 A 的 `list_price` 与「明码牌价」在中文语境里容易被读成「售价牌价」，若担心歧义，选候选 B 的 `list_price_scaled` 更稳。**这一项不阻塞口径定稿，key 名定下前不要把枚举值写进对外文档。**
